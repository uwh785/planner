The application layer holds use cases and ports. It depends only on the domain.

- `auth`: session use cases and the authenticated HTTP client.
- `sync`: the sync engine (push then pull, backoff, status), the scheduler that decides when it runs and the coordinator that binds both to the signed-in user. See the Sync section of the root README.
- `planner`: what the screens use, built per signed-in container by `createPlanner`. `PlannerQueries`: `dashboard()` (the four counters, with the web's overdue rule through `TaskFilter.overdueAt`, and up to ten in-progress tasks), `tasks(scope)` (by list and by the web's status filter, split into open and completed), open counts per list, plain and `LiveQuery` versions that rerun on `container.dataChanges` (fires after local writes and applied pulls; `reload()` reruns for results that age with the clock). `ListUseCases` and `TaskUseCases` (validation is the domain's), `CompletionWindow` (the five-second undo window; flushed on background, on leaving the screen and before sign-out), `Notices` (the one line the screens say out loud, kept as a message key and params so it follows the language).
- `i18n`: the message catalogs (`messages/es.ts` is the source of the typed `MessageKey`, `messages/en.ts` must match it), `translate(locale, key, params)` (`{name}` placeholders; a `{one, other}` message picks its form from `{count}`), and `LocaleService` (the chosen language, Spanish by default, saved through the `LocaleStore` port; never rejects, so a broken store cannot block startup). Framework-free, so a desktop client can share it.

Completing a task: the backend has no reopen transition and ignores status on update, so completion is final. It is queued as the timer op `complete` (`{at}`) behind the task's create. A `conflict` answer to it means the server already has the task completed, so the entry is cleared; `not_found` retries five times and then parks as blocked. The undo window exists because of this: nothing is written until it elapses, and a process kill inside it loses the tick.
