Screens are containers that wire application use cases to presentational components.

- `SessionGate` picks the screen from the session state (`useSession`): loading, retry when the saved session is unreadable, the auth flow when signed out or expired, `SignedInNavigator` otherwise.
- `navigation/SignedInNavigator` opens the user's database, builds the planner services and shows a native stack whose first screen is the bottom tabs (`routes.ts` has the typed route map; `TabBar` is the web's mobile bar; screens draw their own header and change without animation; Android's back button pops the stack, then returns to Panel, then leaves the app).
- Tabs: `PanelScreen` (the four counters, today's classes when there are any, and the active task cards with Pause and Complete, refreshed every 30 seconds for the clock), `TasksScreen` (quick add into the selected list, status and list filters, task cards with Start, Pause and Complete, collapsed Completed, undo window). Both flush the undo window when they lose focus (`useFlushCompletionOnLeave`), since tabs stay mounted, `ScheduleScreen` (the weekly classes one day at a time, Monday-first tabs opening on today, Add class from the header), `ConfigScreen` (language, Lists entry, account and Sign out, sync status line, development-only controls).
- `TaskDetailScreen` (opened from any task card): header with Back, Edit and Delete, description, priority, due date and status, the ring card (ticks every second while the task runs, every 30 seconds with reduced motion, never when idle), the timer actions and the subtasks. Complete uses the same undo window as the lists; Start and Pause write at once. Not found shows the "no longer exists" message.
- Above the tabs: `ListsScreen` (list management, opened from Config), `TaskEditScreen` (also the estimated duration), `ClassEditScreen` (add on the selected day or edit a class; typing a known subject lends its teacher and color unless they were chosen; Save, confirmed Delete) and `ListEditScreen` (explicit Save, confirmed Delete, a guard on unsaved changes that is lifted only for the one navigation after a save or delete, `useDiscardGuard.leaveWith`).
- `AuthScreen` validates, calls `login`/`register` and maps typed errors to short messages (`authMessages.ts`).
- `StartupErrorScreen` explains a misconfigured build instead of crashing (in the saved language).
- `SyncStatusLine` reads the sync status (`useSyncStatus`); `DevTaskButton` (development builds only, on the Config screen) queues a sample task for manual sync tests.
